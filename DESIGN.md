# Torrent TV design system

## Direction

**Night Screen.** The picture is the show; the interface steps back. A cool near-black ground, white type in one quiet variable face (Inter), translucent white pills instead of outlined boxes, and a single saffron accent kept for the few things that must stand out: progress, Best match, the selected marker, counts and badges. Depth comes from tonal fills and the backdrop scrims, not from hairlines or glass. It is not a trademark clone of any streaming product. Static artwork, typography and selection state carry the experience; autoplay video backgrounds are intentionally excluded.

Night Screen replaces "Velvet Booth" (ticket #29, aubergine-black with saffron as the primary-action fill and Bricolage Grotesque). Decisions recorded in spec #51 and its tickets (the approved 1920x1080 mockup boards: Home, Navigation open, Movie title page, Series page, Search, Downloads, Settings, Player controls); the earlier prototypes are kept in `docs/design/direction-prototypes.html`:

- Ground: neutral, slightly cool near-blacks (`#0a0b0f` to `#262a35`), so poster art supplies the colour.
- Accent: refined saffron, `#f2a93b`, for progress, Best match, the selected-tab marker, counts and badges. Never a large button fill and never a focus colour.
- Focus: white. A focused button, chip, tab or rail item turns solid white with ground-coloured text, inside a white ring (the look is built by #53; the tokens are here).
- Font: one bundled variable family, Inter (SIL OFL 1.1, bundled offline, Latin plus Latin Extended for Romanian diacritics, about 87 KB). Headings 700 to 800 with slight negative tracking, body 400 to 500, tabular figures for numbers.
- Artwork: a single blurred poster layer behind rows, following the focused title, with a scrim that guarantees text contrast. On a TV the layer is the half-resolution art scaled up with no blur filter and no crossfade: measured on a 2023 Samsung (Tizen 9), the blur and the per-key motion stalled the main thread 300-1000 ms per frame, so every TV takes the lean path and snaps. Posters themselves stay sharp. Titles without artwork get a designed tinted backdrop, never an empty hole.
- One visual language for the browser app and the TV client. Both import the same token file. Density differs by platform through the type scale and target sizes, never through a second palette.
- Dark only. There is no light theme.
- Signature: the backdrop follows focus. Beside it, source facts (resolution, codec, size, seeders) sit in a spec strip set apart from titles.

Hard limits that hold for every screen: an original look, legibility at 3 m on the TV, an obvious focus state that does not depend on one CSS feature, no looping decorative animation, contrast at WCAG AA, and CSS that stays inside the support floor below.

## Tokens

The single source is `clients/shared/design/tokens.css` (custom properties, all prefixed `--tt-`) and `clients/shared/design/fonts.css` (the bundled face). Entry points import them as `@torrent-tv/shared/design/fonts.css` and `@torrent-tv/shared/design/tokens.css`: `clients/tv/src/main.tsx` (so the Tizen, webOS and Android builds get them), `web/src.tsx`, and `desktop/src/App.tsx`. Screens read tokens with `var(--tt-...)` and never copy a hex value. `clients/shared/src/design-tokens.test.ts` checks the file: required names, contrast, the forbidden-CSS list, motion limits and the font rules.

The legacy variables (`--teal`, `--panel`, `--ink` and the rest) are gone from the TV client: ticket #30 rewrote `clients/tv/src/tv.css` and `performance.css` on the `--tt-` tokens, and `clients/tv/src/design-tokens.test.ts` fails if a legacy variable, a colour of its own (other than video black and subtitle white) or a literal TV font size under 26 px comes back.

The browser app (`web/style.css`) and the desktop shell (`desktop/src/shell.css`) are on the tokens too (ticket #31) and define no legacy variable: every value is a `--tt-` token, plus a few layout locals prefixed `--w-` (rail widths, gutter, text measure). `web/style-contract.test.ts` reads both sheets and fails on a `--teal`-style variable, a copied hex color, a looping animation, a transition outside opacity, color, transform and shadow, text under 13 px, a removed outline, a missing reduced-motion or forced-colors block, and a backdrop scrim that would drop muted text below 4.5:1 over an all-white poster.

The translucent fills are checked twice: `--tt-text` and `--tt-text-muted` hold 4.5:1 on either fill over each surface, and on either fill over the title-page text scrim (`--tt-scrim-text`) over an all-white picture (8.6:1 and 5.8:1 on the rest fill, 7.6:1 and 5.2:1 on the selected fill). `--tt-text-subtle` falls to 3.7:1 in that over-art case, which is why it is for the plain ground only. Rules. Saffron marks progress and a few chosen things (Best match, the selected tab, counts, badges); it is never a large button fill, never focus, and never the only signal of a state. Status colors always travel with an icon or a word (`Downloaded`, `Needs attention`). Because warn sits close to saffron in hue, warn text uses `--tt-warn` on a surface and never on a saffron fill. Translucent colors are written `rgba()`; the TV engines reject 4- and 8-digit hex.

### Type

One family, Inter. `--tt-font-sans` is `"Inter", system-ui, "Segoe UI", Arial, "Helvetica Neue", sans-serif`. Weights: `--tt-weight-regular` 400 and `--tt-weight-medium` 500 for body, `--tt-weight-semibold` 600 for labels and buttons, `--tt-weight-bold` 700 for row and section headings, `--tt-weight-black` 800 for titles and the display size. Headings take slight negative tracking: `--tt-tracking-display` -0.025em on titles and the display size, `--tt-tracking-heading` -0.02em on page headings, `--tt-tracking-snug` -0.01em on row headings. Line height `--tt-leading-display` 1.02 for titles, `--tt-leading-tight` 1.15 for headings, `--tt-leading-body` 1.45 for body. Numbers (times, sizes, counts, speeds) use tabular figures: `font-variant-numeric: var(--tt-figures)` (`tabular-nums`, the font's `tnum` feature is kept in the subset).

| Role | Web (`--tt-text-*`) | TV at 1920x1080 (`--tt-tv-text-*`) |
| --- | --- | --- |
| meta, captions, badges, chips | xs 13 px | meta 26 px |
| secondary and body | sm 15 px, md 16 px | body 30 px |
| lead, row headings | lg 20 px | lead 34 px |
| page heading (Downloads, Settings) | xl 26 px | heading 56 px |
| title on its page | 2xl 36 px | title 88 px (movie), title-compact 80 px (series, longer names) |
| hero | display 52 px | display 92 px |

The web scale is unchanged by #52; the browser alignment ticket may revisit it. On the TV nothing a viewer must read goes below 26 px: `clients/shared/src/design-tokens.test.ts` keeps every `--tt-tv-text-*` token at 26 px or more and in rising order, and `clients/tv/src/design-tokens.test.ts` rejects a literal font size under 26 px in `tv.css`. Numbers in source facts keep weight 500 or more.

Font loading. The bundled files are `clients/shared/design/fonts/inter-latin-wght.woff2` (32.8 KB) and `inter-latin-ext-wght.woff2` (56.1 KB), built from the official Inter 4.1 release by `tools/subset_inter.py`: weight axis 400 to 800, optical size pinned to 14 (the text design, which holds up best at 3 m), split by unicode-range so the Latin Extended file (Romanian ă ș ț, both comma and cedilla forms) loads only when such a letter appears. Provenance, hashes and the licence are in `clients/shared/design/fonts/README.md` and `OFL.txt`. `fonts.css` declares the face only inside `@supports (font-variation-settings: normal)` (Chromium 62+). webOS 4 runs Chromium 53, which cannot apply a weight axis and would render the file's default instance (Regular) at every weight, so it keeps its platform sans. Tizen 5 (Chromium 63), Android TV and every browser get the real face. Both TV startup pages set their `html, body` font from the token too, because an inline `font-family` there would otherwise win over `:root`, and their `var()` fallbacks repeat the token colours (the TV token test checks they match). `font-display: swap` keeps text visible while the local file loads. The TV builds inline the font into `app.css` as a data URI (Vite library mode, covered by the page `data:` source in the CSP), which makes `app.css` about 187 KB; the browser build emits two hashed `.woff2` files. The shared token test reads each woff2's character map and fails if a Romanian letter or basic Latin character is not drawn by the file whose unicode-range claims it.

### Spacing, shape, targets

- Spacing is a 4 px scale: `--tt-space-1` to `--tt-space-9` = 4, 8, 12, 16, 24, 32, 48, 64, 96. Layouts use margins, not `gap`, on the TV engines (ADR-0006).
- TV safe area is 5% of the canvas: `--tt-tv-safe-x` 96 px, `--tt-tv-safe-y` 54 px. Text and focus rings stay inside it; backdrops and the scrim bleed to the edge. The canvas is fixed at 1920x1080 and scales for 4K output.
- Radii: `--tt-radius-sm` 6, `--tt-radius-md` 10, `--tt-radius-lg` 16 (cards, dialogs), `--tt-radius-xl` 20 (large cards and rows), `--tt-radius-pill` (buttons and chips are fully rounded in this direction; screens move to pills as they are restyled). Depth comes from tonal separation and the backdrop, not from glass or `backdrop-filter`.
- Targets: `--tt-target-web` 44 px minimum, `--tt-tv-target` 72 px for TV buttons and rows. One exception: the left rail rows are 56 px high, because the rail holds up to 15 destinations and 15 rows at 72 px do not fit 1080 px; their labels stay at body size.

### Focus

Focus is two independent signals so it survives an engine that drops one declaration: a solid white outline (`--tt-focus-ring`, 4 px on TV via `--tt-focus-width-tv`, 3 px in the browser via `--tt-focus-width-web`) drawn outside an offset gap (`--tt-focus-offset`), plus a white inner edge (`--tt-focus-edge`) on the element's own border. On the TV add a scale of `--tt-focus-scale-tv` and the soft white halo `--tt-focus-shadow-tv` (`0 0 0 5px` white at 25%, then a drop shadow, as on the mockups). The ring sits outside the element, so it contrasts with the surrounding surface (at least 14.3:1) and stays visible on any fill. The ring went from saffron-light to white with #52 (the accent is no longer a focus colour); the focused white fill (`--tt-fill-focus`) arrives with #53. The browser uses `:focus-visible`; the TV stylesheet uses `:focus` because Chromium 63 and 53 lack `:focus-visible`, and TV focus is never pointer-driven. Neighbouring posters in a focused row may dim to about 70% opacity; the focused one never does. `tools/webos_ipk.py` requires the solid outline beside any `button:focus` box-shadow.

As built on the TV: only poster cards scale under focus (`.poster-card:focus`). On capable engines the scale eases over `--tt-dur-fast` on `transform` alone, a compositor property; on lean engines (every TV browser — Tizen, webOS, Android TV WebView — and any Chromium before 70, which `clients/tv/src/capability.ts` marks with the `lean-graphics` class on the root) it applies at once, because the transition cost a layer-tree rebuild per frame there and stretched every D-pad move's settle time (ticket #49). The backdrop layer carries no `will-change`, which doubled paint cost per move. every other control keeps its geometry, so lists never shift while the remote moves, and `performance.css` pins `transform: none` for them. The 70% dim is not built, because it needs `:focus-within` (Chromium 60+). A ring is clipped by an `overflow` container, so rails, grids and scrolling lists reserve at least 16 px of padding around their focusable children; a control inside a clipped card (a season pack header) lives outside the card's `overflow` instead.

### Motion

Transitions only, on opacity, color, transform and shadow: `--tt-dur-fast` 120 ms (focus, press), `--tt-dur-base` 180 ms (menus, rails), `--tt-dur-slow` 260 ms (backdrop crossfade, sidebar), easing `--tt-ease-out`. Nothing loops; no `infinite` and no `@keyframes` in the shared sheets. Never animate `width`, `height`, `top`, `left` or a blur radius. The browser honors `prefers-reduced-motion` by dropping transitions to zero; the TV has no such setting and keeps the short ones.

### Backdrop art

- One blurred layer per screen, behind the rows, sourced from the focused or featured title's backdrop (falling back to its poster). Never one blur per card.
- The blur is static. Change the layer by crossfading opacity over `--tt-dur-slow`; never animate the blur. Browser blur radius is `--tt-backdrop-blur-web` (36 px). On the TV render the layer at half resolution and scale it up with `transform`, with the smaller radius `--tt-backdrop-blur-tv` (18 px); Tizen and webOS GPUs choke on a full-resolution blur. The layer is never larger than the viewport, and the TV never uses `backdrop-filter`.
- Artwork opacity is `--tt-backdrop-art-opacity` (0.55). A scrim sits over it: `--tt-scrim-top` to `--tt-scrim-bottom` vertically, and `--tt-scrim-text` (84% ink) directly under any text block. That keeps body text at 4.5:1 or better over an all-white poster.
- No artwork: the backdrop becomes `--tt-ink` with a soft radial of `--tt-accent-soft`, and the poster fallback shows the title's initial on `--tt-raised`. That state is designed, not an error.
- TV as built (`clients/tv/src/backdrop.tsx`): two stacked layers inside the viewport, 960x540 and scaled by 2, blurred at `--tt-backdrop-blur-tv`, only one on at a time; a change preloads the image, then flips the `on` class, so the cost is one decode and one opacity fade. A card or button opts in with `data-art="<url>"` (empty means no artwork and brings the fallback back); a control without `data-art` leaves the art alone; the art follows focus after 180 ms, so a held D-pad key loads only where it stops. Home and the list screens start from the featured or first title, the detail screen holds its own title's art (`follow={false}`, drawn sharp, see below), and Setup shows the fallback only. Text blocks that sit on art (the hero, the detail header) carry their own `--tt-scrim-text` panel.
- Title page art is the exception to the blur: opening a title shows its own picture as it is. The TV detail screen passes `sharp` to the backdrop: one full-resolution 1920x1080 layer, no blur, no scale, at full opacity (not `--tt-backdrop-art-opacity`), so there is no filter pass for an old GPU. The TMDB backdrop is used; a poster stands in only when there is no backdrop and is placed full height at the right edge (`poster-only`) instead of being cropped into a stretched slice. Legibility comes from the scrim, not the blur: `--tt-scrim-bottom` rising from the bottom edge and a left-to-right fade from `--tt-scrim-text` through `--tt-scrim-top` to clear, plus the `--tt-scrim-text` panel under the title block. The browser's title overlay does the same: an undimmed, unblurred backdrop under a left scrim that fades to transparent. Not verified on hardware: how much of the picture the title panel leaves visible at 3 m, and the poster-only placement on a real set.
- No autoplay video backdrops.

## Web and desktop layout

The browser app and the desktop shell are pointer and keyboard first, so they use the dense end of the shared scale (15 px secondary text, 44 px minimum targets) and the same palette as the TV, never a second one. Dark only.

- Rail. At 1100 px and wider the left rail is 232 px with labels. From 641 to 1099 px it narrows to 72 px of icons, each with a `title` and a visually hidden label so every item keeps its name. At 640 px and below it becomes a bottom bar with the label under each icon and the selected item marked by a bar on top. The desktop shell keeps a 224 px rail and drops it to a row above the page under 720 px.
- Page. One column of content with a 32 px gutter (24 px on tablets, 16 px on phones), no horizontal scroll from 320 px up. Lists collapse to one column on phones; the title detail becomes a full-screen sheet.
- Home hero. A text panel on the `--tt-scrim-text` scrim beside a sharp 16:9 artwork tile; under 1100 px the columns narrow, on phones the tile moves above the text.
- Detail. A sharp poster beside the title block over the title's backdrop image (not blurred and not dimmed, under a left scrim that fades out), so the picture reads clearly and the page has no blurred layer. Season tabs follow, then a series shows its episode list, and OK on an episode swaps the list for that episode's full-width Versions view (see "Series page: episodes, then Versions" below); there is no per-episode artwork.
- Backdrop that follows focus. `web/backdrop.tsx` draws one fixed layer behind the page: two image slots that crossfade by opacity over `--tt-dur-slow`, blurred by `--tt-backdrop-blur-web`, under the `--tt-scrim-top` to `--tt-scrim-bottom` gradient. Poster and library cards publish their title's artwork on `pointerenter` and `focus`; the layer rests on the featured title (Home and catalog views) or the first library title (library views) and resets when the view changes. No artwork leaves the tinted radial of `--tt-accent-soft` on `--tt-ink`. Neighbouring cards in a rail dim to 72% while one is hovered or keyboard-focused.
- Version row. A spec strip: resolution with HDR, then quality and codec chips, size and seeders, and the action as a saffron label. Wide rows (640 px and up, by container query) keep it on one line; narrow rows put the facts under the spec. The row is a button for the action plus a separate Details toggle; the toggle is never nested inside the action.
- Focus. Every control uses the global `:focus-visible` ring (3 px, `--tt-focus-ring`, offset 3 px) and a white border; the search field shows the same ring on its wrapper. Selected tabs, switches and menu rows carry a second signal besides saffron (weight, a bar, a check mark or a knob position).
- Motion. The only transitions are on opacity, color, transform and shadow; `prefers-reduced-motion` drops them to zero and the rail arrows scroll without smoothing. Nothing loops: the loading skeleton and the connection-test dot are static, and the volume OSD has no flash.
- Player. The bar is `--tt-controls-surface` over a bottom scrim that is already `--tt-scrim-text` where the title sits; menus are solid `--tt-menu-surface`. The controls keep their order and commands and group into transport, volume, tracks and view.

## Categories

Tracker > Categories and My Library > Categories are one design with one image source. They list Category families (about nine, not the raw tracker categories), each as a wide 16:9 image tile. The server owns the mapping (`internal/domain/families.go`) and the art, so every device shows the same thing; the clients draw `/api/v1/catalog/families` and `/api/v1/library/families`.

- Tile. The image fills the tile (sharp, no blur). The family name sits at the foot at lead size (TV 36 px, web `--tt-text-xl`), with one small line under it: the count and `Newest: <title>` (`12 titles · Newest: Dune`). The text lives on a `--tt-scrim-text` panel at the foot of the tile, so it clears 4.5:1 over any image. A tile is a poster card: it takes the shared focus ring and scale on the TV, and the global `:focus-visible` ring and a slow image zoom on hover on the web. No overlay icons or badges.
- Family art. A title's backdrop (poster when it has none) picked on the server from the family's ten best titles with artwork, deterministic per calendar quarter (Jan 1, Apr 1, Jul 1, Oct 1). When no title qualifies the tile shows the family's bundled artwork: an aubergine-to-ink gradient with a saffron glow and one line motif in saffron (a film strip for Movies, a screen for Series, viewfinder corners for 4K & UHD, a sparkle for Anime, a face for Animation & Kids, mountains for Romanian, a stadium for Documentaries & Sport, a record for Music videos, four tiles for Other). Every family always has an image; the bundled SVGs are designed, not placeholders.
- Family page. Opening a tile shows the family's titles (Tracker) or managed items (My Library) with a chip row: All plus one chip per raw category inside the family. Tracker adds the existing sort (and, on the web, kind) controls. The selected chip carries a check mark and weight as well as the saffron border. Audio-only categories and CAM/TS appear in no family and stay reachable through Browse filters.
- TV. Tiles are three to a row in a wrapped flex grid (no CSS grid on webOS 4), 512x288 px, in the content focus region from row 1, tagged `data-landing="card"` so landing focus finds the first tile. Tile images load by grid row around focus (`lazy-art.ts`, `useRowReach`: two rows either side, rows already loaded stay until they are more than four rows away, so the window slides and the page does not hold every tile it has shown); a tile outside that window keeps its geometry and surface as a `poster-pending` block. Back from a family page returns to the tile that opened it; Back from a title page returns to the card it was opened from.
- Web. A CSS grid of `minmax(280px, 1fr)` tiles, one column on phones; every image is `loading="lazy"`.

## Information architecture

Home prioritizes Continue Watching, then discovery. The left rail groups Home/Search, My Library, Tracker, and settings/jobs. Canonical titles open into movie versions or show → season → episode → source. Source rows always expose resolution, source/codec where known, size, and seeders.

## TV interaction

The sidebar is compact until focus enters it. Left from content column zero opens it; Right restores the exact prior content control and collapses it. As built, the rail is a 400 px element whose panel (a `::before` layer behind the buttons) is slid left with a `transform` so only the 120 px icon strip shows when compact, and slides home when open; the labels fade by `opacity`. Both are compositor-driven, so opening it never re-lays out or repaints the page and the main thread only flips a class. On lean engines (the `lean-graphics` root class) the panel and the labels snap to their end states instead of animating; animating `clip` was the first attempt and held each route change open for the length of the transition on a TV-class CPU (ticket #49). The panel has no outer shadow, because the rail's paint containment clipped it anyway. Rows and columns are explicit, vertical movement clamps to the nearest available column, and Back unwinds detail/dialog/player layers before exiting.

Landing focus. A screen opens with the cursor on its first card, never on the header Refresh button (`clients/tv/src/landing.ts`). Screens tag what they draw with `data-landing`: `card` for a tile or row (poster, category tile, job, download, project link), `control` for a primary control that outranks the cards (the Home hero button, the Search field), `chrome` for header furniture. The target is the tagged element with the lowest `data-focus-row`, then `data-focus-col`; a screen with no cards falls back to its first untagged content control (the first setting), and the chrome only when nothing else exists after a short grace period. Cards that load late still receive the cursor, but a landing lets go as soon as the viewer presses a navigation key or moves focus, so it never yanks. The rule applies to menu route changes, closing a title page or dialog with no card to return to, a finished search (first result), and category pages; a screen that opens a sub-view itself calls `requestLanding()`.

Starting playback unmounts Catalog, so App keeps a `NavSnapshot` (route, open title and episode target, query, category, sort, the focused card key; `clients/tv/src/nav-snapshot.ts`) written only when the viewer starts a play or opens a download, never by a next-episode swap. When the Player closes, Catalog remounts with it as the optional `initialNav` prop (absent means the old behaviour: Home, nothing open): the route and filters return, an open title is fetched again through the normal open path (so Resume shows the new position) and focuses Play or Resume, and a list focuses the saved card when it still exists. If the title cannot be reopened the route list shows with the usual notice. The snapshot is dropped when the server changes or is forgotten.

Player keys follow the Wake model. On hidden controls the first directional press only wakes them and never seeks: Left or Right lands on the timeline (the next Left or Right seeks), Up or Down restores Control focus (the toolbar control last used, `play` by default). OK on hidden controls wakes them and activates that control, so Audio and Subtitles open on the first press. With a toolbar control focused, Left and Right move along the toolbar, and Up moves to the timeline. Seeking by one Seek step happens only with Timeline focus (Left and Right, focus stays on the timeline; Down returns to the remembered toolbar control) or with the fast-forward and rewind keys (and Next and Previous, a larger step; see Remote keys), which work in every state without moving focus and, with the controls hidden, show the position on the OSD without waking the controls. A seek records a pending target that owns the shown position and current time until AVPlay's `seekTo` succeeds, a playtime within 1 second of the target arrives, or 2 seconds pass; stale playtime is ignored meanwhile, and a seek error is shown as a status message and routed to recovery. Held keys: `event.repeat` is ignored for Enter, Back and Play/Pause, directional repeats keep moving focus, and timeline repeats keep adding Seek steps that commit after the last one. Focus stays on the pressed control after every action, including opening and closing a Player panel. The hide timer re-arms after every key press, a seek does not hold it open, and when it fires the focused control is remembered for the next Wake. If the active element is outside the control list, focus falls back to the remembered control, never the first. Dialogs remember and restore their launcher.

## Remote keys

One table for every remote, handled in the Player by `playerAction` and `PlayerKeyController` (`clients/tv/src/player.ts`, `player-keys.ts`). A key matches by `event.key` name or by `keyCode`, whichever the platform sends. Android TV delivers the key names natively (ticket #27); Tizen needs each name registered through `tizen.tvinputdevice.registerKey` (`registerMediaKeys` in `platform.ts`, one try/catch per key, because a name the firmware lacks throws); webOS delivers the keyCodes without registration.

| Action | Key names | keyCodes | In the Player |
| --- | --- | --- | --- |
| Play | `MediaPlay` | 415 | Plays. Explicit, never toggles. |
| Pause | `MediaPause` | 19 | Pauses and saves the position. Explicit. |
| Play/Pause | `MediaPlayPause` | 10252 | Toggles. Ignored while held. |
| Stop | `MediaStop` | 413 | Saves and leaves the Player, like Back. |
| Rewind | `MediaRewind` | 412 | One Seek step back (10 s). |
| Fast-forward | `MediaFastForward` | 417 | One Seek step forward (10 s). |
| Previous | `MediaTrackPrevious` | 10232 | Skip step back (60 s). |
| Next | `MediaTrackNext` | 10233 | Skip step forward (60 s). |
| Previous episode | `ChannelDown` | 428 | Series: saves progress and starts the previous episode. Otherwise the OSD says "No previous episode". |
| Next episode | `ChannelUp` | 427 | Series: saves progress and starts the next episode. Otherwise the OSD says "No next episode". |
| Back | `GoBack`, `BrowserBack`, `XF86Back`, `Back` | 27, 10009 (Tizen), 461 (webOS) | Closes a Player panel, else leaves. |

Rules:

- Channel up and down are the episode skip (the episode queue): `POST /downloads/{id}/next-episode` and `/previous-episode` resolve the sibling from the series hierarchy. The Player saves the current progress first, drops any pending seek target, and swaps the player to the sibling; a result that arrives after the Player closed or suspended is discarded. A movie, or the first or last episode, gets a brief OSD notice instead. The Wake model is untouched: the keys never move Control focus, and held repeats are ignored. The media-track keys keep the plain seek: Next and Previous skip a larger step (`SKIP_STEP_MS`, 60 s) rather than change item. They use the same pending seek target, commit timer and clamping as Rewind and Fast-forward, so any mix of the four accumulates into one committed seek.
- Rewind, Fast-forward, Next and Previous work with the controls hidden or visible, repeat while held, and never move Control focus. Hidden, they show the new position on the OSD and leave the controls hidden (the Wake model above); visible, they re-arm the hide timer. Play, Pause and Play/Pause reveal the controls through the existing playback state change and do not move focus either.
- A media key typed while a text field has focus is ignored by the Player (`isEditableTarget`).
- Outside the Player the media keys are not mapped at all (`remoteAction` in `navigation.ts` returns null for them), so D-pad navigation, OK and Back are unaffected. Channel up and down are only the episode skip inside the Player.
- Tizen registers the eight media names plus `ChannelUp` and `ChannelDown`. The colour keys (`ColorF0Red` to `ColorF3Blue`) are deliberately not registered: nothing in the client uses them. The `tv.inputdevice` privilege is already in `clients/tizen/config.xml` and required by `tools/tizen_wgt.py`; the key names themselves are not listed in the config or the validator.
- Not verified on hardware: that each physical remote sends these codes (Channel up and down as episode skip is likewise unverified on hardware) (Samsung and LG remotes differ, and many have no Previous or Next button), that Tizen 5.0 firmware accepts every name, and that Channel up and down reach the page on both platforms. See the Remote keys rows in `docs/TIZEN.md` and `docs/WEBOS-VERIFICATION.md`.

## Player controls surface

This section sets the look and sizes only. It does not touch the Control, Wake and Seek rules in "TV interaction" above: the toolbar order, Timeline focus, Wake behavior, the hide timer and the pending seek all stay as written. Ticket #30 redesigned the bar and its menus inside these rules (as built, below); `player-keys.test.ts` and the lifecycle tests pin that the controls, `data-focus-row` and `data-focus-col` did not move.

- Surface: the bar is one layer, `--tt-controls-surface` (92% surface) over a bottom scrim. Menus (Audio, Subtitles, speed, and the like) are solid `--tt-menu-surface` on `--tt-overlay` borders. No `backdrop-filter`, so text contrast never depends on the video behind it.
- Position and safe area: the bar sits inside the TV safe area (`--tt-tv-safe-x`, `--tt-tv-safe-y`). The timeline spans the bar, which spans the safe width.
- Sizes at 3 m: toolbar buttons are at least `--tt-tv-target` (72 px) high with 40 px icons and a visible label at `--tt-tv-text-meta` (nine labelled buttons only fit the safe width at that size); the time labels use `--tt-tv-text-body`, the title `--tt-tv-text-lead`; menu rows use `--tt-tv-target` height and `--tt-tv-text-body`. The timeline is `--tt-tv-timeline-height` (12 px) and grows to `--tt-tv-timeline-height-focus` (20 px) when Timeline has focus, with the standard focus ring on its handle. In the browser, targets are `--tt-target-web` or larger.
- Focus: the standard ring from "Focus" on every toolbar control and menu row. The pressed or open control keeps a `--tt-accent-soft` fill so an open Player panel is distinguishable from a merely focused control.
- Auto-hide motion: the whole bar fades with one opacity transition of `--tt-controls-fade` (200 ms) in both directions, with no slide and no per-control animation. Hidden controls get `visibility: hidden` after the fade so they cannot take focus, and the Wake handling restores focus to the remembered control. When the hide timer's behavior changes, it changes in the interaction rules, not here. With reduced motion in the browser the fade is instant.
- OSD feedback (volume, mute, seek position) uses the same surface and fades with `--tt-dur-base`; the volume flash plays once per change, never in a loop. On the TV the status message keeps its last text mounted while it fades out.
- Layout as built: a heading row (the title, with the episode code, left; the current Audio and Subtitles choice, muted, right), the timeline, the two time labels, then the toolbar in the existing order with a wider break before Audio and before Back. The timeline button keeps one 36 px height; only the drawn track grows to 20 px on focus, so nothing below it moves. Audio, Subtitles and Options carry `aria-expanded` and the accent-soft fill plus bottom bar while their Player panel is open. The Player panel sits at the top right inside the safe area, 700 px wide, scrolling when it holds more than six rows.

## Information priorities

Each screen shows what helps the viewer decide the next action. Three levels: **primary** (always visible, largest), **secondary** (visible but muted, or shown on focus or hover), **hidden by default** (behind a details control, a focused-row line, or removed). This is a display decision only; the screens keep fetching the same data. Omit a fact when it is unknown instead of printing a placeholder such as "codec unknown", "Year unknown" or "—". "Source" here means the quality attributes of a release, as in the glossary.

Observed before the redesign: poster cards on both clients show seeders, tracker names and source counts, and the web card repeats the rating twice; the web hero and detail header show a summed seeder count; library cards print raw release and file names; Downloads rows print release name, file path and file index; the web Player heading shows the tracker and a transfer-mode string; the catalog toolbar prints tracker-sync prose on every page. On the TV specifically: the hero fell back to "N versions, up to N seeders", the title header printed tracker names and "Year unknown", version rows always printed the file name and "codec unknown", Downloads rows ran to ten lines with the file path, index and peers, Jobs rows printed job ids, the Player heading was the file path, and Settings showed the eight connection tests at all times.

Rules that follow. A card answers "what is this and where am I with it", so state beats tracker data. Seeders, size and codec appear at the decision point, the version row, because that is where they change a choice. The release name is evidence, not a headline: it is never the largest text when parsed title data exists, and raw release rows (no catalog match) keep it as the title because nothing better exists. Empty and error states state the cause and the next action in one sentence each.

### Info panel

The Info button opens the extended description of a title: the `GET /catalog/titles/{id}/info` answer, ordered by the priorities above (the order is the shared `infoView()` in `clients/shared/src/title-info.ts`). It is on the title page actions row and beside the Home hero's primary action. Cards and rows only ever read the cached `releaseDate`; they never wait on the Info request, and a date that is not cached shows the year alone. Dates are written with manual English month names (no `Intl`, which Tizen 5 and webOS 4 only partly ship).

On the TV it is a 1160 px side sheet over a veil, drawn at the root of the screen (not inside `.tv-content`, whose `contain` would clip a fixed layer). It owns its own focus region, `info-panel`, so the D-pad cannot leave it: row 0 Close (focused on open), row 1 the summary block (meta line, tagline, overview, genres), then one row per cast member, then the fine print. The cast scrolls by D-pad because the sheet's scroll follows focus, and long overviews scroll the same way because the summary block is itself a stop. Back closes it and returns focus to the Info button that opened it (`detail-info`, or `hero-info-<id>` on Home); the Player's Control/Wake model is untouched. Chromium 53 floor: flex and block only, no grid, gap or sticky, `rgba()` colours, text at or above the 26 px floor, no looping motion (the loading skeleton is static). While loading it says "Loading details…" over three static bars; with nothing to show it says "No extra details available" and keeps the card's own overview if there is one. Cast photos are lazy `img` elements with an initials fallback and are capped at twelve by the server.

Focus rows, title page actions: row 1 holds Play or Resume (col 0), Choose version (col 1), Favorite (col 2), Refresh data (col 3), and Info (col 4), appended so no existing column moved. Home hero: row 1 holds the primary action (col 0) and Info (col 1).

On the web it is an overlay dialog with `aria-labelledby` pointing at the title heading, the shared overlay focus trap (Tab cycles inside, the page behind is `inert`), Escape closing only the dialog, and focus returning to the Info button. It scrolls inside itself, caps at 760 px, and fills a phone width.

## Best version

The primary Play on a title page prepares one Source chosen by `rankSources()` (`clients/shared/src/sources.ts`, unit-tested); the button names the choice ("Play and download · 1080p WEB-DL · 4.2 GB") and **Choose version** (web: the picker, whose default sort is Best match; TV: focus moves to the version list) shows every version in the same order. Resume still replaces Play. Ranking, in priority order:

1. Junk captures (CAM, TS, HDCAM, screeners, found in the quality or the release name) go last and lead only when nothing else exists.
2. Downloaded beats managed (queued, downloading, partial) beats a new Prepare.
3. A swarm of 3 or more seeders beats a thinner one; when none qualifies, seeders alone decide.
4. Resolution tier: 1080p, then 4K with HDR or 20+ seeders, 720p, plain 4K, lower, unknown. A small box progressing a 60 GB remux is a worse default than 1080p.
5. Quality: BluRay, REMUX or WEB-DL, then WEBRip, HDTV, unknown.
6. More seeders, then the smaller file. Ties keep the server order.

For a series the target is the resume episode, else the target episode of the opened link, else the first episode of the selected season; sources that name another season or episode rank after those that match. A season that only has packs shows no Play (the pack controls stay).

The TV title page opens with focus on Play or Resume (Favorite when there is nothing to play); Back stays one press Up and the Back key still closes the page. The season tab that opens first is the link's target, else the season of the saved progress, else the first.

### Series page: episodes, then Versions

Below the hero and the season tabs (both unchanged: same rows, columns and behavior) a series page is in one of two states. EPISODE LIST (the default) lists the season's episodes, one focus stop each: number and name, air date or Upcoming, version count, the progress bar and the library badges. VERSIONS replaces the list, full width, for one episode: the header `Versions · S02 · E05 · <name>` ("Versions" in the accent colour), that episode's Sources ranked by `rankSources()` with the first marked "Best match", then a "Complete season" section with the season packs (`packSources`) and their actions always visible, so nothing sits behind a Show or Hide. Unknown episodes are the last stop of the list; OK on it opens its files as `Versions · S02 · Unknown episodes`. A season that has packs but no episode list yet shows the Versions view straight away, headed `Versions · Season 2`, with no list to go back to.

- Same component family as Info > Seasons > Season > Episode: one column, one level at a time, Back pops a level, no competing panes. An episode row is the Info episode row (`.info-row` pieces: `E04 · name`, a facts line, the saffron `›` chevron as the only "opens something" cue; the library badges sit before the chevron). On TV the row spans the card and uses it: a 256x144 still (16:9; the Info panel keeps its 160x90), the full `E04 · name` on one line, the facts line, and when the season info has a synopsis a muted two-line clamp under it (`.episode-synopsis`; a `max-height` of 2.8em backs `-webkit-line-clamp` on old engines; the series overview is never used here); badges and chevron sit at the right edge. The Versions view opens with the Info episode block (breadcrumb `Show › Season 2 › E04`, a larger still, the `S02E04 · air date · runtime · rating` line, name, synopsis, director and writer lines), then "Choose a version" and the rows. TV and web both use the shared `.info-*` classes and `episodePageView()` (clients/shared) rather than their own copies.
- Detailed info is optional. Season info (`/api/v1/catalog/titles/{id}/info/seasons/{n}`) is requested once per season, 400 ms after the season shows, never on a focus move, and kept for the page; an unavailable answer is kept and changes nothing, and a failed request is forgotten so coming back to that season asks again. Without it a row and the block use the title detail: code, name and air date, the title's backdrop (else poster) as the still, and the series overview as the synopsis. No spinner or empty box appears while it loads. Stills load only near focus (`useListArtReach`).
- A version row is one line of fixed columns so rows line up: resolution, Best match slot (the marker on the first row, an empty slot of the same width on the others), quality chips, size and seeders (tabular numbers, right aligned), then the library state and action. A second line carries the tracker and audio and the release name, which truncates with an ellipsis (always visible here, unlike the focus-only name on a movie's list).
- Layout of the list state: below the season tabs, TV: one column as wide as the card, left-aligned on the same edge as the Versions view (web: unchanged, a column up to 760 px, full width on narrow windows) headed `Episodes · Season 2` ("Episodes" in the accent colour, the same heading style as `Versions · …`). The old fixed 760 px pane and any side preview are gone. The TV list scrolls on its own up to 720 px (about three and a half rows, so the next row shows there is more) and the focused row is revealed. Surfaces are translucent: the TV season browser, and on the web the season bar, the episode column and the Versions view, sit on `--tt-card-surface` (58%) so the title's sharp backdrop shows. Their text carries `--tt-text-shade`, a dark halo of two static `text-shadow` layers, which keeps it readable over a bright picture; the shade is set on the card (a button does not inherit `text-shadow`, so the transparent episode rows set it themselves) and is reset to none on text over a saffron fill (`button.primary`, the Best match marker, the Versions action pill, `.danger-button:focus`). It is never transitioned or animated, and the page scrim is unchanged: a stronger scrim would only be a second, wider way to lower the card's transparency, while the halo darkens just the ground under the glyphs and leaves the art visible between them. The TV backdrop is already full-screen behind the page; on the web the series body carries the title's backdrop on below the hero (`.series-art`, sharp, only when the title has a backdrop). No `backdrop-filter`, no blur and no box shadows: transparency is an rgba token and the halo is the only shadow. Rows are transparent inside their card (no second layer, so alpha never compounds); the selected row's facts line takes `--tt-text`, because its saffron tint lifts the surface under it. Not verified on hardware: how much of the picture the 58% card lets through at 3 m and how the halo reads on a bright still, and the full-width rows against real titles on a set.
- The selected episode carries a tint and a bar (`.episode-tile.selected`, `aria-current`). It opens on the link's target, else the saved progress, else the first unwatched episode, else the first, and follows focus after 150 ms. A data refresh (the 3 s series poll) never changes selection or focus and never leaves Versions; a Versions view whose episode disappeared falls back to the list.
- OK or Right on an episode does not play: it opens Versions with focus on the Best match, and OK there plays or prepares it. Hero Choose version opens the Versions view of the target episode. Playing the best version without opening Versions stays on the hero Play or Resume button.
- D-pad map. Hero and season tabs: as before; Down from a season tab goes to the selected episode, or to the first version row while Versions is open. Episode list: Up and Down within it, Up from the first episode goes to the active season tab, Right or OK opens Versions, Left does nothing, Down from the last stays put, Back leaves the page. Versions: Up and Down through the version rows and then the packs, Up from the first row goes to the season tab, Left (from the first column) or Back returns to the list with the episode Versions was opened from focused, Right and Down at the ends stay put. OK on a season tab leaves Versions for that season's list. Pack actions are plain stops in the same view (regions `episodes` and `versions`; rows and columns are the existing data-focus attributes). The Back handler pops Versions from anywhere on the page before it leaves the page, unless a dialog is open.
- The open Versions view is part of the navigation snapshot (`NavSnapshot.versions`, the episode key), so Back from the player reopens the title page in the same Versions view, focused on the version played. A restored view is used once.
- The page scrolls and keeps the focused item in view (`revealElement`). Layout is flexbox only (Chromium 53).
- Web: clicking an episode replaces the list with the Versions view inside the title overlay: a Back control ("Back to episodes") and the breadcrumb `Title › Season 2 › E04 › Versions` above the same header, rows with the web version row layout (it stacks at narrow widths, so the view reads on a phone). Back returns to the list with the episode focused; Escape pops Versions before it closes the overlay; the Close button closes the overlay from anywhere.
- Not verified on hardware: the D-pad map, focus visibility, row fit at 1920x1080 and 3 m legibility have only been exercised in happy-dom tests.

## Support floor for shipped CSS

Everything shipped to the TV runs on Chromium 63 (Tizen 5) and Chromium 53 (webOS 4): no `gap`, `inset`, `aspect-ratio`, `:is()`, `:where()`, `:focus-visible`, `min()`, `max()`, `clamp()`; no 4- or 8-digit hex; grid only with a flex fallback (the TV stylesheet uses no grid at all, and keeps the empty-handed `@supports not (display: grid)` block that `tools/webos_ipk.py` requires); custom properties are fine (Chromium 49+) but not inside `@media` queries; and comments are scanned too, so do not spell a forbidden construct in a comment. Authored CSS ships verbatim (`cssMinify: false`). `tools/tizen_wgt.py` and `tools/webos_ipk.py` reject violations at pack time; `clients/tv/src/chromium53-css.test.ts` and the design-token test cover the sources.

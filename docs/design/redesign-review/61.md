# #61 TV Player controls and panels in the new look: screenshot review

What changed: the Player's look, to the "Player controls" board (8). No boxed bar any more: the heading moved to the top of the screen over its own scrim, and the timeline, time labels and toolbar sit straight on the picture over a bottom scrim, all in the one layer that fades with one opacity transition. The toolbar is nine round icon buttons with labels under them (the focused circle white, Play/Pause larger, wider breaks before Audio and before Back); the timeline draws the downloaded range under the played range with an always-visible white handle; the time labels are elapsed and remaining; the Audio, Subtitles, Options and Playback information panels are solid sheets with 72 px rows. The toolbar order, every `data-focus-row`/`data-focus-col`, the Control/Wake/Seek rules, the declared D-pad maps and all playback behaviour are unchanged.

## How the captures were made

Headless Chromium at 1920x1080 under the Tizen 5 user agent (lean graphics), the synthetic household of `tools/tv_perf/fixture.mjs` and the AVPlay stand-in from `tools/tv_perf/tv-driver.mjs` (a black "video" 25 minutes into 100). `make screens-tv` (`--only player-controls`) produced the journey's Player shot; the other Player states (Pause focused, each panel open, Playback information) are not stops on the journey, so a throwaway CDP script walked the same journey to the Player and pressed the remote keys from there (Down, Right twice and OK for Audio, Back, Right and OK for Subtitles, and so on). "Before" is the integration branch tip (032630e: #52, #53, #63, #65, #66) built into a separate dist; "after" is this branch; same fixture, same script.

## Deviations and reasons

- **Toolbar focus has no outline around the button.** The #53 focus model draws a solid outline beside the halo on every control, but Chromium 53/63 draws outlines as rectangles (rounded outlines need Chromium 94), so a round button would get a square box around a 132 px column. The circle's white fill, the halo and the label turning white are the signals; nothing changes size. The webOS validator rule (no `button:focus` box-shadow without an outline) still holds: the halo lives on `.player-toolbar [data-player-control]:focus .player-glyph`.
- **Audio and Subtitles labels drop the track count** ("Audio (1)" before; the board says "Audio"). Nine labels only fit a 132 px column without it, and the heading already names the current choice. The count stays in the accessible name ("Audio, 1 track").
- **The choice line keeps the app's wording** ("Audio English · Subtitles Auto") rather than the board's "Audio · English 5.1 · Subtitles · Romanian": the channel layout is not in the saved preference, and the line is unit-tested as is.
- **The episode code reads "S01E04"**, not the board's "S01 · E04", to match the code everywhere else in the app.
- **Icons are 36 px (44 px on Play/Pause)**, the board draws 34 px in every circle: the larger glyph keeps Play/Pause reading as the primary at 3 m.
- **Top scrim is `--tt-scrim-text` (84%)**, the board uses 70%: the heading has to hold on a bright picture, and it also carries the text shade.
- **The buffered range is the download's progress**, refreshed when the Player polls (while getting ready and while waiting for a segment), not a live AVPlay buffer reading; the Player adds no polling for it.

## The subtitle notice in the fixture

The "No Romanian or English subtitle was found." status in both captures is real behaviour, not an artefact: with Subtitles on Auto the Player looks for included, built-in and online Romanian and then English subtitles, and the fixture has none, so the Player says so. A real server with no subtitles for a file shows the same line. It now sits under the heading instead of at the top edge.

## Checks

- D-pad: `node tools/tv_perf/dpad.mjs --only player,player-audio,player-subtitles,player-options` exit 0 (93 checks); the maps did not change, since no stop moved.

That harness does not visit the Player, so a separate run timed keydown-to-second-frame on 18 toolbar and timeline moves under 6x CPU throttle: median 11.2 ms and worst 18.5 ms before, median 11.2 ms and worst 19.3 ms after.

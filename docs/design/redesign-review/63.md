# #63 Browser app aligned to the new icons, controls and focus: screenshot review

What changed: the browser app (and the desktop shell where it shares the sheet) takes the TV vocabulary that #53 set: the TV's line icons drawn by the browser's own icon component, the app mark, borderless translucent pills, the white fill on the focused or hovered primary control, saffron kept for progress, Best match, selected markers and counts, and secondary actions behind round icon buttons or a More menu by the boards' rules (Refresh data on the title overlay, Delete download on Downloads). Page layouts are unchanged, the rail keeps its items (the six-hub regrouping is #64), and the web type scale stays as it is.

## How the captures were made

`make screens-web` (the #65 script: `node tools/tv_perf/screens.mjs web`, the built browser app against the synthetic household at 1440x900 and 390x844). "Before" is the integration branch tip (#52, #53, #65 in) captured with the same script; "after" is this branch. Hover, keyboard focus and the open More menu are not stops on the journey, so they were taken with a throwaway CDP script over the same fixture and build (Tab to walk focus, Enter to open, a mouse move to hover). The no-sideways-scroll check ran the same journey at 320x700 and read `scrollWidth` against `clientWidth` on every step: 320 = 320 on all 21 screens.

Point by point:

- **Layout and spacing:** unchanged. Buttons keep the 44 px target; button horizontal padding grows from 16 to 20 px to suit the pill shape. Downloads rows drop the 1 px border and move to the 20 px card radius. The title overlay's action row is shorter (three 44 px round buttons instead of three labelled ones), so it no longer wraps on phones.
- **Type:** button weight 500 → semibold 600, primary bold; no size changes, the 13 px floor holds (style contract green).
- **Colour and accent:** no button is filled with saffron anywhere in the browser app or the desktop shell. Saffron remains on progress, Best match, the selected bar, the switch's on state, counts, the app mark, the selected episode's edge, the row chevrons and links.
- **Focus:** `:focus-visible` stays, with two signals: the 3 px white ring outside the offset plus a fill change (white pill on compact controls; the selected fill on rows; danger fill on a destructive action). Hover mirrors focus without the ring: the primary turns white, secondaries and rows go one fill step up. Rows inside clipping cards draw the ring inset. Forced-colors and reduced-motion blocks are unchanged and still pass.
- **Primary vs secondary:** primary = `--tt-fill-strong` + bold, white on hover/focus; secondary = `--tt-fill` pills or round icon buttons; tertiary and destructive actions in More.

## Deviations and reasons

- **The desktop shell's section nav was restyled, a deliberate deviation from the spec.** The spec's out-of-scope line (#51) keeps the desktop shell to "the token values and font". The shell's nav shares the sheet the browser rail now uses, and left as it was it drew the current page in `--tt-accent-soft` and the hover in `--tt-raised`, the old accent-tinted selection the redesign removed everywhere else. So it takes the browser rail's states (`desktop/src/shell.css`): hover one fill step (`--tt-fill`), the current page on `--tt-fill-selected` with a short saffron bar, keyboard focus white (`--tt-fill-focus`), and the app mark in place of the "TT" monogram. No layout, page or behaviour of the shell changed.
- **Selected chips, tabs and the current rail item are not white at rest** (the boards draw the selected sort chip, filter chip and season pill white). Same decision as the TV (#53): white is where the cursor is, and a white selected chip beside a white focused one leaves the viewer guessing. Selected = lighter fill + bold + short saffron bar.
- **Secondary pills are not white on hover**, only on keyboard focus; the primary is white on both. With a mouse, every pill under the pointer turning white would flash white across rows of controls as the pointer moves; one fill step up is the hover signal the tokens already define for it (`--tt-fill-selected`, "hovered or selected").
- **Fields keep the 3:1 edge** (the Search board draws the field on the fill with no edge): an input still needs a visible boundary (DESIGN, WCAG 1.4.11); the TV kept it for the same reason.
- **The Home hero's Info stays a text pill** and the title overlay has no "Choose version" button for a movie: the first belongs to the Home ticket's hero (#55, mirrored on the web later), the second would duplicate the version rows that sit directly under the actions in the browser overlay.
- **The card rating keeps the ★ character** in the card's text line (the TV draws a star icon since #53): the browser card's meta line is a single text string that tests and screen readers read as such; replacing it is a markup change beyond this ticket's controls and focus scope.
- **Delete download is the only item in a card's More menu.** The board's More also holds Details; the browser keeps Details as the visible disclosure on the row (page structure stays), so More holds the destructive action alone.
- **Icons are copied, not imported**: the browser app does not depend on the TV client, so `web/icons.tsx` carries the same shapes and `web/icons.test.tsx` (which does import the TV module in the test only) fails if the two sets drift.

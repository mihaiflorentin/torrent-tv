# #62 TV startup, Setup, empty states and the Error panel in the new look: screenshot review

What changed: the first and worst moments, in the Night Screen vocabulary. The startup page shows the saffron app mark over the app name in white (it was a saffron word). The Error panel moves to the content edge with the status word "Error" in the danger colour, a white heading, the cause muted and one next action (it was a centred salmon heading over three lines). Setup starts at the 168 px content edge with the app mark, a 56 px screen heading, found servers as one column of Settings-style rows and Manual address under a section label instead of a hairline. Empty states lose their bordered panel and become a heading plus one muted line on the screen, and every one now says the cause and the next action in one sentence each. The screen notice, the preparing dialog and the Player's getting-ready panel lose their hairlines; the preparing dialog becomes its own sheet instead of borrowing the Settings panel. Content, behaviour, focus rows and columns and the Setup D-pad map are unchanged.

## How the captures were made

None of these screens is a step of `make screens-tv` (its journey starts from Home with a saved server), so a throwaway script beside it drove the same harness: the fixture server, headless Chromium at 1920x1080 under the Tizen 5 user agent (lean graphics) and the journey driver. It captured the startup page with `app.js` blocked (at once, and again after the 8 s slow-boot message), the Error panel by throwing an uncaught error over Home, the Search and Downloads empty states by searching for a word nothing matches, Setup through Settings › Change server address with a stubbed `getNetworkInfo` so Rescan finds the fixture server, and Setup on a first run with no saved server and no discovery on the device. The same script ran on the integration tip (before) and on this branch (after).

## Copy changes (one sentence of cause, one of next action)

- Empty catalog: "The catalog may still be syncing. Wait a minute and press Refresh, or check that a tracker is enabled in Settings." → "Wait a minute for the catalog to sync and press Refresh, or turn on a tracker in Settings."
- No downloads: "... press Play and download. It appears here while it transfers." → "... press Play and download; it shows here while it transfers."
- No categories: "Categories appear after the first catalog sync. Open Settings and choose Fetch latest." → "Choose Fetch latest in Settings to run the first catalog sync."
- Error panel: "Please tell the household admin about this message." and "Press Back to exit." → "Tell the household admin what this message says, then press Back to exit."
- Startup: a slow boot adds "If nothing changes, restart the app."; a failed boot adds "Restart the app; if it fails again, tell the household admin."

## Deviations and their reasons

- **The startup page stays centred** while the other screens moved to the 168 px edge: it shows only the mark, the name and one line before any screen exists, and a centred splash reads as the app starting rather than a broken screen.
- **The Error panel adds the word "Error"**: the spec pairs every status colour with a word, and the danger colour now marks that word instead of a 64 px heading.
- **Empty states keep no action button**: their next action names an existing control (Refresh, Clear, Settings, Fetch latest). Adding a button would add a focus stop to many screens' D-pad maps; the six-hub ticket (#54), which removes the header Refresh, is where a Refresh action inside the empty state belongs.
- **Not reworded here**: the title page's "No versions yet" line ("The trackers have no release ... Press Refresh data to search them again.") already gives the cause and the action, and the title page ticket (#56) moves Refresh data into More, so it owns that wording.
- **Setup keeps the html ground's saffron glow** (top right): it belongs to the shared ground from #52 and every screen without a backdrop shows it.

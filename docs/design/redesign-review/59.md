# #59 TV Downloads rows with actions behind More: screenshot review

What changed: the Downloads screen becomes the board's compact list. The heading line carries the storage used against the Allocation; filter chips with counts (All, Active, Downloaded, Paused, Needs attention), Sort and the find field share one line; each torrent is one 136 px row (thumbnail, title with episode, state with a slim bar and one line of facts, size) with Play, Pause or Resume and More on every row. Delete download, Details and Show files move into the More sheet from #56; Delete keeps its confirmation. The row holding focus gets `active-row` from the navigation layer, which brings its actions up.

## How the captures were made

`node tools/tv_perf/screens.mjs tv --only downloads` (the #65 script: headless Chromium at 1920x1080, Tizen 5 user agent, lean graphics, the synthetic household). "Before" is the integration tip 89761fd (#52, #53, #54, #56, #61, #63, #65, #66); "after" is this branch. The other states (second row active, More open, Details open, the delete confirmation) are not journey stops; they were taken with a throwaway CDP script over the same fixture and build (real key events: Down, Right to More, OK, OK, Down, OK), not committed. ## Deviations and reasons

- **Actions stay drawn on every row** (the board draws them only on the focused row and the size on the others): the ticket asks for one focus band per row, and adding or removing buttons as focus moves would re-lay out rows on every D-pad press. At rest they are quiet; the active row brings them up. The size stays visible on every row, left of the actions.
- **No ring around the active row**: the focused button already draws the white ring; a second ring on the row would put two on screen. The row says "active" with the selected fill instead.
- **The moving bar is 240 px, not 360 px**: the state line has to hold the percent, the bar and "speed · time left · Playable now" beside the always-drawn actions.
- **Sort stays** as a chip-styled cycle button on the tools line (not on the board): it is an existing feature.
- **The find field is a field, not a pill, and has no search icon**: inputs keep the 3:1 edge the #53 vocabulary gives text fields; the placeholder says "Find a download".
- **The selected chip is the selected fill with the saffron bar, not white**: white is reserved for focus (#52/#53 decision).
- **Thumbnails, the rows below the first screenful and the Allocation arrive 400 ms after the screen opens**: measured, drawing everything with the route change put the Downloads route at 155 to 185 ms against its 150 ms budget (baseline about 130); with the first screenful only, it settles at 93 to 110 ms. The thumbnail is the title's w780 backdrop (`/backdrop-small`), the only small landscape art the API has; with no title (or no art) the 176x99 slot stays the raised surface.
- **Fixture coverage**: the synthetic household has no paused, failed, queued or multi-file download, so the Paused and Needs attention rows, Resume, Retry and Show files appear on screen only in the happy-dom tests (`downloads.test.tsx`, `busy-controls.test.tsx`), not in these captures. Chip counts read "Paused 0" and "Needs attention 0" here.

## D-pad

Maps `downloads`, `download-more` (new) and `download-delete` in `clients/tv/src/dpad/maps/library.mjs`, declared before the code changed and mirrored in DESIGN.md "Downloads (TV)". Tools line: Left/Right along it (Left from All opens the rail), Up stays, Down to the rows in the nearest column. Rows: Up/Down in the nearest column (More to the More below), Left from Play opens the rail, Right at More stays, OK on More opens its sheet on Details; the sheet's Back or Close returns to More; Delete download opens the confirmation (Cancel, Delete download; Back returns to More). Opened file rows sit in the columns of Pause and More so Down from More lands on a file's Play, never Remove (the `files` group, optional because the fixture has no multi-file torrent). `node tools/tv_perf/dpad.mjs --only downloads,download-more,download-delete`: 99 checks, all hold.
